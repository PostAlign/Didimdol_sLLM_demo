iPhone FP32 실행 진단

실험마다 새 페이지에서 시작합니다. 페이지가 예기치 않게 다시 열리면 중단된 기록을 표시하며 자동 재시도하지 않습니다. 모델 정밀도는 FP32입니다.

기존 방식의 GPU 가중치는 약 1,023 MiB입니다. 순차 로딩은 2c와 전체 모델 실험에 적용되며 가중치 약 423 MiB와 2 MiB 전송 버퍼를 사용합니다. 토큰마다 가중치를 다시 읽으므로 생성 속도가 느려질 수 있습니다. 연산 임시 메모리는 별도입니다.

상주 실험은 ORT 세션을 생성하지 않습니다. 저장된 가중치 실험은 전체 모델 로드에서 파일 준비가 끝난 뒤 실행하세요. 파일 준비를 위해 전체 로딩이 성공할 필요는 없습니다.

1d는 작은 모델 세션을 유지하면서 같은 GPU 장치에 전체 가중치를 올려 검증합니다. 작은 모델의 추가 자원은 별도 기록되며, 전체 모델 추론 성공을 뜻하지 않습니다.

토크나이저 실험은 전체 로드와 같은 토크나이저를 준비하며 모델 가중치는 적재하지 않습니다. 전체 로드는 토크나이저 준비 후 가중치를 적재합니다.

결과 표와 기기 정보는 이 브라우저에 남아 탭을 닫아도 유지되며, 최근 결과가 위에 표시됩니다. 실험은 한 번에 한 탭에서만 실행하세요. 추론 중에는 0.5초 간격으로 GPU 요청량·파이프라인 수·WASM heap이 바뀔 때마다 기록되어, 첫 추론 중 종료 시 마지막 샘플이 남습니다.

실험 시작 버튼을 누르면 실행을 위해 페이지가 한 번 다시 열립니다. 2c의 120초 관찰은 추론 없이 세션을 유지하며, 생성 완료와 관찰 완료를 따로 기록합니다. 토크나이저 비교는 같은 설정에서 기존 JSON과 미리 변환한 데이터를 번갈아 실행하세요.

중단 원인은 기기 로그로만 확정할 수 있습니다. 실험 전에 설정 → 개인정보 보호 및 보안 → 분석 및 향상에서 iPhone 분석 공유를 켜 두고, 중단 뒤에는 같은 화면의 분석 데이터에서 그 시각의 JetsamEvent-…ips 또는 com.apple.WebKit.WebContent 파일을 찾아 위의 기기 로그 파일 입력에 넣으면 중단된 행과 시각순으로 짝지어 reason·풋프린트·프로세스 최대치·시스템 여유 메모리를 기록합니다. 리포트 하나가 여러 종료를 담을 수 있으며(다음 종료 시각에 함께 기록됨), highwater는 프로세스별 한도를 넘은 상태에서 시스템 압박이 왔을 때 우선 종료된 것입니다. 파일을 옮길 수 없으면 기기 로그 메모에 파일명·reason·풋프린트를 직접 적어도 됩니다. 손으로 적은 메모는 파일로 덮어쓰지 않습니다. 파일 시각은 기기 현지 시각이며, 표의 기기 로그 칸과 내보내기의 *Local 필드가 같은 기준으로 적혀 있습니다. 반복 사이 대기는 연속 실행이 결과에 영향을 주는지 비교할 때 사용합니다.

메모리 비교는 같은 전송 크기에서 1b·1c와 2c·3을 각각 비교하세요. 1c는 토크나이저를 유지한 채 전체 가중치를 검증합니다. 2c는 전체 모델 세션만 준비하며 추론 준비 완료를 뜻하지 않습니다. 각 항목은 3회 반복할 수 있고, 중단 뒤에는 자동 재시도하지 않습니다.

준비

같은 기기·릴리스·런타임에서 전송 크기와 캐시 조건을 비교해 주세요. GPU 계측이 부분 관측이면 전체 할당 이력을 확인할 수 없습니다.
